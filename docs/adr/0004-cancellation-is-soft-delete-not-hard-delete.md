# 取消一律採軟刪除，不做真刪除；需求/規格的取消沿用既有自由狀態欄位，不套用任務的嚴謹狀態機

最直覺的「刪除」做法是把資料真的從資料庫移除，但這個系統的核心價值就在於靠報工、重工回合等歷史記錄回推「這個人本季/本月大概能扛多少工時」（ADR-0002 已經因為同樣理由把「完成」設計成軟性下架、而非查無此項）。若取消是真刪除，一旦被取消的項目底下已經有報工或重工回合，這些歷史紀錄要嘛跟著消失（工時統計失真），要嘛變成指向不存在項目的孤兒資料。因此決定：取消一律做成新增「已取消」狀態的軟刪除，資料不動，只依照既有「完成」的下架規則從看板/清單消失。

需求與規格的狀態欄位本來就是管理職手動、系統不驗證轉換的自由欄位；已取消對它們而言只是這個自由欄位多一個合法值，沿用同一套「自由切換、無復原限制」的行為。任務的狀態則是嚴格驗證的狀態機（start/complete/pause/resume/reject）；已取消因此比照「暫停」的做法，記錄取消前的狀態供復原，而非套用需求/規格那種可自由切換的彈性。刻意不讓需求/規格的取消也走任務那套嚴謹機制，是因為它們的狀態欄位一直以來就沒有被系統驗證過，強行加上任務等級的嚴謹度會是這次改動裡唯一的例外，不符合它們原本的設計精神。
